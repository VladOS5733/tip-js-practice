Отдельно указать:

Синхронный код: сообщения A (глобальный лог), B (начало async-функции до await) и C (лог после вызова async-функции).

Очередь микрозадач: обработчик Promise D и продолжение после await E.

Почему таймер с задержкой 0 не выполняется немедленно: setTimeout передает коллбэк в очередь макрозадач (таймеров), которая обрабатывается только после того, как стек вызовов опустеет и завершатся все микрозадачи (Promise).

Изменится ли вывод при удалении одного обработчика Promise: Нет, относительный порядок остальных меток сохранится, так как синхронный код всё равно выполнится первым, а таймер — последним.

Организация кода
Кратко описать ответственность файлов:

Файл	Ответственность
api/server.mjs	Готовый локальный HTTP-сервер (маршрутизация, CORS, обработка запросов и отдача JSON).
src/api-client.js	Низкоуровневый клиент: формирование URL, выполнение fetch, установка тайм-аутов, обработка HTTP-статусов и парсинг JSON.
src/task-api.js	Доменный слой: валидация фильтров перед запросом и проверка схемы полученных задач и категорий.
src/variant.js	Конфигурация индивидуального варианта (номер и объект фильтров).
src/main.js	Точка входа клиентского приложения, объединяющая работу клиента и доменного модуля для вывода результата.
Объяснения:

fetchFn передаётся в createApiClient для внедрения зависимости (Dependency Injection). Это позволяет в тестах подменять реальный сетевой запрос моками (заглушками) без обращения к сети.

HTTP-ошибки проверяются отдельно от сетевых, так как при HTTP-ошибке сервер ответил, и мы можем прочитать тело ответа (JSON с кодом и деталями), а при сетевой ошибке (например, нет соединения) ответа от сервера вообще нет.

JSON после разбора всё равно проверяется по контракту, потому что даже при статусе 200 OK сервер может прислать JSON с неверной структурой (например, строку вместо числа в id), что вызовет ошибки при дальнейшей работе с данными.

Вывод
В ходе практической работы был реализован асинхронный HTTP-клиент на базе fetch. Были изучены принципы работы Event Loop (разделение синхронного кода, микрозадач и макрозадач). Реализована обработка различных типов ошибок: ожидание Promise (не блокирует поток), HTTP-ошибки (статус 4xx/5xx с чтением тела ответа), сетевые ошибки (сбой соединения), неверный формат ответа сервера, тайм-аут и явная отмена через AbortController. Каждый тип ошибки корректно классифицируется и оборачивается в ApiError для удобной обработки на уровне бизнес-логики.
